# Policy Observatory research methodology

Current version: **`policy-observatory-methodology-v1`** (`apps/web/src/lib/research/methodology.ts`).
A material methodological change creates a new version; this document always describes the current
one, and a publication always states which version it used.

## Governing principle

CrawlPact earns research authority by making evidence, methodology, denominators, limitations,
provenance, and corrections visible — never by using authoritative-sounding language. Publications
avoid phrasing such as "the definitive AI crawler database," "most websites block AI crawlers," or
"industry standard" unless the underlying study design genuinely supports the exact claim (see
`RESEARCH_CLAIM_CLASSIFICATION.md`).

## Registry source policy (Layer A, what this version actually covers)

Every figure is computed from a pinned, immutable `registry_versions` release via
`getRegistryVersionSnapshotMap()` — the same read path production evaluation and historical scan
rendering use. Never the live, mutable `crawlers` table; never the static Markdown crawler
directory. See `docs/registry/CRAWLER_REGISTRY_GOVERNANCE.md` and
`docs/registry/PHASE_15_FULL_SOURCE_REVERIFICATION_REPORT.md` for how the underlying crawler
records were themselves verified.

## Research unit

One immutable registry release (`registry_version_id`). Not a sample — the Registry Observatory
counts every crawler entry in a given release exhaustively, so no sampling methodology or
confidence interval applies to Layer A figures.

## Missing data

Never treated as "false" or silently excluded. A crawler with no recorded `lastVerifiedAt` is
counted under "never verified," not silently dropped from `crawlerCount`.

## Small-cell suppression

Not applicable to Layer A (exhaustive population counts, not a sample). A future Layer B study
would suppress any cohort below 20 observations (`SMALL_CELL_THRESHOLD`), rendering "Insufficient
sample" instead of an unstable percentage.

## Comparability and trends

A release-history entry is described as a single "change since previous release" until at least
`TREND_MIN_COMPARABLE_RUNS` (3) comparable published releases exist — never a "trend" from two
points.

## Registry/ruleset pinning

A publication's `registry_version_id` is fixed at generation time and never silently advances. A
correction recomputes from the _same_ pinned release; a registry change after publication requires
a new, separate publication, not a silent rewrite of the old one (see
`RESEARCH_CORRECTION_AND_RETRACTION_POLICY.md`). No ruleset version applies to Layer A findings,
since they don't evaluate customer policy data.

## Reproducibility

Every published statistic is generated by code, never hand-typed. Each publication carries a
SHA-256 checksum (`apps/web/src/lib/research/publication-checksum.ts`) computed over its
deterministic content — excluding the `generatedAt` timestamp and operator-authored
`correctionLog`, since including either would make the checksum spuriously unstable across
reproductions that changed nothing real. Independently recomputable via
`reproduceResearchPublication()` and `pnpm research:integrity:verify`.
