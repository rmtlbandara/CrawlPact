# Pilot Interview Guide

Status: current-authoritative. For manual, owner-led interviews only (§82). Avoid leading
questions (§83) — e.g. never "Isn't monitoring extremely useful?" or "Wouldn't $19 be cheap for
an agency?"; use neutral wording instead.

## Questions

1. What made this problem (AI crawler policy) relevant to you?
2. What do you currently do instead of using a tool like this?
3. What did you expect CrawlPact to do, before you tried it?
4. What was confusing?
5. What information was most useful to you?
6. Which feature mattered most?
7. Would you return to CrawlPact after your initial setup? Why or why not?
8. What would make ongoing monitoring valuable to you?
9. Which plan seemed appropriate for your situation?
10. What prevented you from purchasing, if anything?
11. What alternative would you use instead if CrawlPact were unavailable? (record the category —
    manual robots review, spreadsheet, SEO crawler, CDN tooling, no process, other — not a forced
    competitor name, per §152)
12. How much human help did you need to get value from CrawlPact?

## Also ask, when relevant (value ranking, §153)

"Which of these mattered most to you?" — offer only real product capabilities, never invented
ones: the AI crawler matrix, evidence/findings, recommended configuration, saved history,
monitoring, timeline/change attribution, reports/sharing, portfolio/Agency workflows.

## Recording

- Do not store raw audio or full transcripts in this repository (§84).
- Record structured findings only, using the coding schema in
  `docs/pilot/PILOT_FEEDBACK_CODING_SCHEMA.md`.
- Never include a participant's name in a GitHub-tracked document — use an anonymous label
  (`I-01`, `P-02`, `A-03`, ...) per `docs/pilot/PILOT_FEEDBACK_CODING_SCHEMA.md`'s labelling
  convention.
- A "How would you feel if CrawlPact were no longer available?" question (the "very disappointed"
  test) may be asked directionally, but its result is never treated as definitive
  product-market-fit evidence from a small cohort (§99, §100).
