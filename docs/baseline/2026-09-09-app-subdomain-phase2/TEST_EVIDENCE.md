## A real bug this phase's own tests caught and fixed

Writing `route-ownership.test.ts`'s `isSensitivePath` tests surfaced a genuine boundary bug before
it ever shipped: `pathname.startsWith("/app")` matches `/apparently-fine` (and `/sign-in` would
have matched `/sign-in-evil`) — a false positive that would have caused the unknown-host fail-closed
check to needlessly reject unrelated paths, not a security hole, but a real correctness defect.
Fixed in `route-ownership.ts` with boundary-aware matching (`pathname === prefix ||
pathname.startsWith(prefix + "/")`) before any other code depended on it. Documented here rather
than silently fixed, per the "no fabricated PASS" instruction — this is exactly the kind of finding
a genuine test-writing pass should produce.
