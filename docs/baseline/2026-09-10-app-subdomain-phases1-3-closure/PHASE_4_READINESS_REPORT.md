## R. Monitoring/observability

**Resolved 2026-09-11 — genuinely, not deferred.** Full findings in
`docs/baseline/2026-09-11-app-subdomain-final-pre-phase4/OBSERVABILITY_READINESS.md`. The
owner's hard security invariant for this work ("no real path-embedded bearer token may be
persisted in observability data") raised a real architectural tension: this codebase has two
routes that embed a bearer credential in the URL _path_, not a header or query string —
`/feed/[token].xml` and `/shared/[token]` — and Wrangler 4.123.0's schema has no
`redact_query_string`-style field at all (verified by reading the installed package's own
`.d.ts`, not assumed from docs), and even if it existed it would not cover path segments.

Rather than accept either of the owner's two proposed fallback architectures (disable invocation
logs entirely, sacrificing per-request monitoring; or build new sanitized application-level
logging), this session ran a controlled Preview-only experiment using only synthetic fake tokens:
a plain, non-secret path segment was logged verbatim (positive control), while every
high-entropy, realistic (256-bit-equivalent) synthetic token — across `/feed/[fake].xml`,
`/shared/[fake]`, a `?continuation=<uuid>` query string, and a custom `console.error()` event —
was automatically replaced with the literal string `REDACTED` in captured telemetry, with zero
special configuration. **Cloudflare Workers Logs redacts high-entropy path and query values by
platform default.** This was independently discovered and proven this session, not read from
Cloudflare's marketing docs.

Consequence: the already-approved, already-deployed-to-Preview Step 1 configuration
(`observability: { enabled: true, head_sampling_rate: 1 }`, no other overrides) already satisfies
the hard invariant, with full per-request monitoring value intact. No `invocation_logs` change,
no new sanitized logging code, and no further architecture decision were needed. This closes
`OWNER_ACTION_QUEUE.md` item 3. Deploying the identical config to Production remains to be done
(not yet applied as of this document) but is no longer blocked on an open design question —
Section 6 of the owner's authorization already covers this deployment.
