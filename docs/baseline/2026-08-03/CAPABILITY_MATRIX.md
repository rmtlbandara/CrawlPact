## Cross-cutting notes

- **`AUDIT_ENGINE_ENABLED` is the single most consequential flag in this matrix** — gates
  capabilities 1, 2, 6, 7. Confirmed read live (not baked into a build) at `status.astro:10`,
  `api/audit/index.ts:64`, and (after a prior fix) `scanner.astro:6`; production value confirmed
  `"true"` this session via direct `wrangler.jsonc` read.
- **The CPU-budget risk is an accepted, explicit tradeoff, not a resolved one** — enabling the
  engine does not resolve the modeled capacity risk; it accepts it at current, near-zero real
  volume (2 users, 9 domains per this session's live D1 count).
- Rows marked "not verified — required access was unavailable" are stated that way deliberately
  rather than inferring production behavior from code presence alone.
