# Phase 16 research security threat review

| Threat                                                   | Applies this phase?                                     | Finding                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SSRF / arbitrary URL fetch / open crawler proxy          | Not applicable                                          | No research fetch code exists this phase — nothing accepts or dereferences an admin- or visitor-supplied URL.                                                                                                                                                                                                                                                                                                                   |
| Source poisoning / corpus poisoning                      | Not applicable                                          | No corpus exists.                                                                                                                                                                                                                                                                                                                                                                                                               |
| Admin CSRF                                               | Reviewed                                                | Every mutating research route (`generate draft`, `submit-review`, `publish`, `correct`, `withdraw`) goes through `requireAdminAction`, which internally calls `requireAdminSession` → `assertSameOrigin` (Origin/Referer check) before any write — the same mechanism every other admin mutation route uses; no separate/weaker path was introduced.                                                                            |
| Admin IDOR                                               | Reviewed                                                | Every publication lookup is by its own primary key (`id`) or `slug`, scoped globally (there is no per-account research data), so there is no cross-account object to leak — the only access-control question is "is this caller a Super Admin at all," which `requireAdminSession`/`requireAdminAction` already answer.                                                                                                         |
| Study/report XSS                                         | Reviewed                                                | All publication text is rendered through Astro's default JSX escaping in `/observatory/*` and `/research/*` — no `set:html`, no `dangerouslySetInnerHTML`, no raw string concatenation into a template anywhere in the new files. Publication content is generated entirely by code from numeric/enum registry data, not free-text admin input, so there is no injection surface even before escaping is considered.            |
| CSV formula injection                                    | Not applicable                                          | No CSV/data-download export exists this phase — see `docs/product/PHASE_16_PUBLIC_RESEARCH_AND_DATA_DOWNLOAD_DECISION.md`.                                                                                                                                                                                                                                                                                                      |
| Unbounded corpus / D1 exhaustion / Worker CPU exhaustion | Not applicable this phase, reviewed for what does exist | `getRegistryObservatorySnapshot`/`getRegistryObservatoryReleaseHistory` read every published registry release once per page render — bounded by the number of registry releases (a handful, manually published), not by any attacker-controlled input. Public pages are cached (`Cache-Control: public, max-age=120` on `/observatory*`, `max-age=3600` on published `/research/[slug]`), further bounding repeat-request cost. |
| Duplicate job / research job starvation                  | Not applicable                                          | No background job exists — publication generation is a synchronous, manually triggered admin action.                                                                                                                                                                                                                                                                                                                            |
| Cross-account data leak                                  | Not applicable                                          | No per-account research data exists.                                                                                                                                                                                                                                                                                                                                                                                            |
| Public query tool over private data                      | Reviewed, avoided by design                             | `/research/[slug]` only resolves a fixed, pre-existing `slug` to a publicly visible publication row — there is no free-text search or arbitrary-domain lookup, matching §131's explicit prohibition.                                                                                                                                                                                                                            |

## Result

No security finding requiring a code change. The dominant mitigation, as with the privacy review,
is structural: most listed threat categories (SSRF, corpus poisoning, job starvation) have no
applicable code surface yet, since Layer B was not built.
