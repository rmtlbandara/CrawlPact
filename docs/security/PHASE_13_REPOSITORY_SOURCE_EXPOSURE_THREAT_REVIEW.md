## Fixes applied this phase

1. `apps/web/src/pages/privacy.astro` — misleading "public documentation" reference reworded.
2. `apps/web/src/lib/json-response.ts` + 2 duplicate call sites — raw exception message no longer
   leaked to clients in production.
3. `pnpm repo-privacy:validate` — new, CI-gated regression check for all of the above going
   forward (package publish config, customer-facing repo-claim language, source maps, internal
   docs under public assets, `PUBLIC_*` secret exposure).

## Residual, disclosed limitations

- Historical exposure cannot be proven absent, only that no current evidence of it was found this
  pass (see `docs/governance/PHASE_13_REPOSITORY_EXPOSURE_AUDIT.md`).
- If a legitimately-authorized past collaborator ever cloned the repository while it was
  genuinely accessible to them, repository privacy settings cannot revoke that existing local
  copy — this is stated explicitly, not glossed over.
