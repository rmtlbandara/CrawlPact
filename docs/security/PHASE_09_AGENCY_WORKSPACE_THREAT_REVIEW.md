# Phase 09 — Agency Workspace Threat Review

Every route added or extended in this phase is reviewed against the prompt's §53 checklist below.
"Mitigation" cites the exact mechanism; "Test" cites the test file that exercises it — filled in
against the final implementation (see the completion report's Security section for the actual test
run results).

| Threat                                  | Mitigation                                                                                                                                                                                                                                     | Test                                                                                                    |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Cross-account portfolio access          | Every workspace query takes `ownerUserId` from `requireSession`'s resolved user, never from a request parameter                                                                                                                                | `workspace-portfolio.integration.test.ts`                                                               |
| Cross-account group access              | Existing `getOwnedGroup` ownership check, reused unchanged everywhere a group ID is accepted (import, bulk actions, export scope)                                                                                                              | `groups.integration.test.ts` (existing) + new bulk/import cases                                         |
| Cross-account domain assignment         | Bulk actions and import re-validate every domain ID against `owner_user_id` server-side before acting, never trust a client-supplied ID list                                                                                                   | `bulk-actions.integration.test.ts`                                                                      |
| Cross-account import-job access         | `portfolio_import_jobs` job-status lookup filters `owner_user_id = user.id AND id = jobId`; a mismatched job ID returns `not_found`, never `forbidden` (no ID-existence oracle)                                                                | `import.integration.test.ts`                                                                            |
| Cross-account export                    | `domainIds`/`groupId` export scope re-validated against ownership per row/group, never trusted from the query string alone                                                                                                                     | `export.integration.test.ts`                                                                            |
| Cross-account bulk action               | Same as domain assignment above                                                                                                                                                                                                                | `bulk-actions.integration.test.ts`                                                                      |
| Cross-account branding                  | `agency_brand_profiles` keyed on `owner_user_id`, upsert path only ever writes the session user's own row                                                                                                                                      | `agency-branding.integration.test.ts` (extended)                                                        |
| Plan-entitlement bypass                 | Every gate (`domainGroupsEnabled`, `csvExportEnabled`, `batchImportLimit`, `agencyBrandingEnabled`) re-read from `getPlan()` server-side at execution time, never trusted from client state or cached across the request                       | entitlement test matrix, §58                                                                            |
| CSV formula injection                   | Import: values starting `=+-@` stored literally, never interpreted; Export: `escapeCsvField` (existing, reused) prefixes a `'`                                                                                                                 | `csv.test.ts` (extended)                                                                                |
| CSV parser abuse                        | Hand-written bounded parser: max file size, max rows, max columns, max field length, all enforced before any row is processed                                                                                                                  | `csv.test.ts`                                                                                           |
| Oversized upload                        | 256 KB hard cap, rejected before parsing begins (`Content-Length` pre-check + a streaming size guard)                                                                                                                                          | `import.integration.test.ts`                                                                            |
| Malformed encoding                      | UTF-8 validated; invalid byte sequences rejected with a generic error, never passed through                                                                                                                                                    | `import.integration.test.ts`                                                                            |
| Duplicate domain import                 | `createDomain`'s existing duplicate check (per-user, per-canonical-origin), unchanged, reused                                                                                                                                                  | `import.integration.test.ts`                                                                            |
| SSRF through imported domains           | Reuses `normalizeTarget()` — the same SSRF-safe normaliser every other domain-creation path already uses; no separate import-specific normaliser exists to drift out of sync                                                                   | existing `normalize-target` unit tests + import-specific fixture cases                                  |
| Import replay                           | `idempotencyKey` unique per `(owner_user_id, key)`; replay returns the stored result, never re-creates domains                                                                                                                                 | `import.integration.test.ts`                                                                            |
| Bulk-action replay                      | Same idempotency mechanism, `bulk_action_jobs`                                                                                                                                                                                                 | `bulk-actions.integration.test.ts`                                                                      |
| Queue replay                            | N/A — no queue is introduced this phase (see `CSV_IMPORT_WORKFLOW.md`); nothing to replay beyond the idempotency case above                                                                                                                    | —                                                                                                       |
| Stored XSS in group/client/agency names | All user-controlled strings (group name/description, agency name, import display names/notes) rendered through the existing React/Astro auto-escaping paths, never `dangerouslySetInnerHTML`/`set:html`                                        | `stored-xss.spec.ts` (new e2e)                                                                          |
| Logo upload content spoofing            | Existing magic-byte sniffing (`agency-logo.ts`), unchanged, reused for the new profile-logo path                                                                                                                                               | existing `agency-logo.test.ts`                                                                          |
| R2 object-key injection                 | Existing `buildLogoObjectKey` (server-generated UUID, never derived from a client-supplied filename), unchanged                                                                                                                                | existing test + new profile-path case                                                                   |
| R2 orphan deletion error                | `findAndCleanupOrphanedLogos` updated to also treat `agency_brand_profiles.logo_url` as a valid reference before treating anything as orphaned (see `AGENCY_BRANDING_MODEL.md`)                                                                | `r2-orphan-cleanup.test.ts` (extended)                                                                  |
| Shared-report token leakage             | Unchanged existing token model (hashed at rest, random 32-byte token); this phase never exposes a raw token in any new list view (import/bulk/branding views never touch share tokens at all)                                                  | n/a — no new surface                                                                                    |
| Private-cache leak                      | Global middleware default (`private, no-store`) applies automatically to every new route; explicit tests assert the header is actually present, not merely assumed                                                                             | `cache-isolation.integration.test.ts`                                                                   |
| CSRF                                    | `requireSession`'s existing same-origin check covers every new POST/PUT/PATCH/DELETE route, since none of them bypass `requireSession`                                                                                                         | covered by existing CSRF test pattern, extended                                                         |
| Session fixation                        | No change to session issuance in this phase; not applicable to new routes                                                                                                                                                                      | n/a                                                                                                     |
| IDOR                                    | Every "get by ID" in this phase (group, job, domain) is ownership-filtered in the SQL `WHERE` clause itself, never checked only in application code after an unscoped fetch                                                                    | IDOR cases folded into each area's integration test file                                                |
| Query/filter injection                  | All filters are Drizzle-parameterised query builders; the portfolio table's free-text search binds via `like()`, never raw SQL string interpolation                                                                                            | reviewed at implementation; no raw `sql` template used for user input anywhere in this phase's new code |
| Export data leakage                     | Column allow-list is fixed server-side (`CSV_EXPORT_WORKFLOW.md`'s exact list); there is no "export all columns" mode                                                                                                                          | `export.integration.test.ts`                                                                            |
| Race with plan downgrade                | Bulk actions and import both re-read `getPlan()` at execution time (not at selection/preview time)                                                                                                                                             | `bulk-actions.integration.test.ts`, `import.integration.test.ts`                                        |
| Race with account deletion              | Existing cascade-delete FKs remove domains/groups/jobs when a user is purged; a bulk action or import mid-flight against a since-deleted account fails its per-row ownership check, reported as `skipped`/`failed`, not a crash                | reviewed at implementation                                                                              |
| Unbounded batch processing              | Import capped at `batchImportLimit` (10/100); bulk actions capped at 100 domain IDs per request — both hard server-side caps, not UI-only                                                                                                      | `import.integration.test.ts`, `bulk-actions.integration.test.ts`                                        |
| Worker/D1 resource exhaustion           | No new synchronous external network call anywhere in this phase (import never scans; bulk monitoring-enable never scans) — the only new per-request cost is bounded D1 reads/writes, measured in `PHASE_09_PORTFOLIO_QUERY_AND_INDEX_AUDIT.md` | performance test suite                                                                                  |

## Additional notes

- **No customer-facing share-revocation route exists yet** (confirmed in the baseline) — this
  phase does not add one; RISK-010's closure is via the daily-cron orphan sweep, not via adding a
  new revocation surface, so no new threat surface is introduced there.
- Every new API route lives under `apps/web/src/pages/api/workspace/**` or extends an existing
  `apps/web/src/pages/api/domains/**` / `apps/web/src/pages/api/agency-branding/**` route — none
  of them are `prerender: true`, and all inherit the standard `requireSession` + Zod-contract
  validation pattern documented in `apps/web/src/pages/api/AGENTS.md`.
