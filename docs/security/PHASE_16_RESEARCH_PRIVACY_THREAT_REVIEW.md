# Phase 16 research privacy threat review

Scope: the Registry Observatory and research-publication code actually shipped this phase. Layer B
(website-policy corpus/collection) items are reviewed as forward-looking, since none of that code
exists yet — see `docs/research/PHASE_16_RESEARCH_CORPUS_DECISION.md`.

| Threat                                              | Applies this phase?       | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Customer-domain leakage into a public publication   | Yes — reviewed            | `buildRegistryLandscapeContent()` reads only `RegistryObservatorySnapshot`, itself computed only from `registry_versions`/`registry_version_entries`. No customer table (`domains`, `scans`, `users` beyond `createdByUserId`) is ever read by any Observatory/research code path — confirmed by reading every new file in `apps/web/src/lib/observatory/`, `apps/web/src/lib/research/`, and `apps/web/src/lib/admin/research.ts` in full. Structurally impossible to leak today, not just policy-forbidden. |
| Account linkage                                     | Yes                       | `research_publications.created_by_user_id` is an internal admin attribution field, never selected or rendered by any public route (`parsePublicationContent`/public `.astro` pages never read it).                                                                                                                                                                                                                                                                                                            |
| Small-cell inference                                | Not applicable            | Registry Observatory figures are exhaustive population counts of CrawlPact's own registry, not a sample of anything that could expose an individual's identity.                                                                                                                                                                                                                                                                                                                                               |
| Research corpus exposure                            | Not applicable            | No corpus exists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Raw URL exposure                                    | No new exposure           | The only URLs surfaced are crawlers' own `officialSourceUrl` values, already public on `/crawlers/[slug]` since Phase 1/15.                                                                                                                                                                                                                                                                                                                                                                                   |
| Private IP scanning                                 | Not applicable            | No research fetch code exists this phase.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| User-agent fingerprinting                           | Not applicable            | No research fetch code exists this phase.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Scan data repurposing (anonymous audit -> research) | Not applicable — verified | No Observatory/research code reads `scans`, `scan_resources`, or `scan_crawler_results`. Anonymous audits remain product usage only, never silently repurposed as research participation, because no code path connects them.                                                                                                                                                                                                                                                                                 |
| Publication mistakes exposing something unintended  | Reviewed                  | `validateResearchPublicationContent` and `pnpm research:validate` scan publication text for unsupported-claim language before it can reach `review` status; a Super Admin still explicitly approves `publish`. No free-text admin input is rendered unescaped (Astro JSX auto-escapes; no `set:html` used anywhere in the new `.astro` files).                                                                                                                                                                |
| Withdrawn-data persistence                          | Reviewed                  | Withdrawal doesn't delete `content_json` — it remains queryable by a Super Admin and is intentionally still rendered (with a banner) at its public URL, which is the documented behaviour (§217), not a leak.                                                                                                                                                                                                                                                                                                 |

## Result

No privacy finding requiring a code change. The strongest mitigation is structural: the Registry
Observatory has no code path capable of reading customer data at all, rather than a policy that
merely instructs it not to.
