# Phase 13 Analytics Privacy Threat Review

**Level 4 document.** Reviews the consent and first-party analytics architecture this phase
introduced.

| Threat                             | Assessment          | Mitigation                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Consent bypass                     | Low                 | GA is only ever rendered by `MarketingLayout.astro`'s SSR check (`consentState === "granted"`) or injected client-side on an explicit Accept click — there is no code path that loads GA without one of these two, both gated on the same `apps/web/src/lib/consent.ts` logic.                                                                                                                       |
| GA loads before consent            | Low                 | No `<script>` referencing `googletagmanager.com` exists in the DOM until consent is granted — verified structurally (`GoogleAnalytics.astro` is conditionally rendered, not present-but-hidden) and by `pnpm analytics:validate`'s static scan.                                                                                                                                                      |
| Consent-cookie tampering           | Accepted, by design | The cookie is untrusted client state and is only ever allowed to control whether _optional_ analytics loads — it has no code path anywhere near authentication, billing, plan entitlement, security features, or audit behaviour. A visitor forging `granted.v1` at worst causes GA to load a page early; a visitor forging `denied.v1` at worst suppresses GA. Neither is a security vulnerability. |
| GA on authenticated routes         | Low                 | `AppLayout.astro`/`AdminLayout.astro` never import `GoogleAnalytics` (structurally confirmed, and enforced by `pnpm analytics:validate`'s explicit negative check on both files).                                                                                                                                                                                                                    |
| PII leaking through page URL       | Low                 | `page_location` is explicitly overridden to `origin + pathname` in every `gtag("config", ...)` call — query strings, hashes, and tokens are never sent.                                                                                                                                                                                                                                              |
| Private report IDs in GA           | Low                 | `/shared/[token]`, `/audit/[auditId]`, `/pay`, `/app/*`, `/admin/*` are all excluded from `isGaEligibleRoute`'s allowlist — GA structurally cannot load on a route carrying a private identifier.                                                                                                                                                                                                    |
| Analytics payload injection        | Low                 | `POST /api/analytics/track`'s Zod schema rejects unknown event names and caps string properties at 200 chars; `trackEvent()`'s `PROHIBITED_PROPERTY_KEY_PATTERN` additionally rejects any property key shaped like PII, server-side, regardless of caller.                                                                                                                                           |
| Unbounded product properties       | Low                 | Same as above — property values are `string(≤200)                                                                                                                                                                                                                                                                                                                                                    | number | boolean` only, never nested objects/arrays. |
| Long-lived anonymous identifiers   | N/A                 | `anonymousId` remains an unpopulated, reserved column — no anonymous identifier is generated by this phase or any prior one. If a future phase needs conversion analysis for anonymous flows, it should use a short-lived, single-flow identifier, not a persistent one — documented as guidance, not implemented (no concrete requirement exists yet).                                              |
| Analytics retention overcollection | Low                 | 18-month bounded purge now exists (`purgeExpiredProductEvents`), closing the previously-unbounded-growth gap (RISK-006).                                                                                                                                                                                                                                                                             |
| Admin analytics IDOR               | Low                 | `/api/admin/analytics` requires `requireAdminSession` (session + `isAdmin`); the dashboard is aggregate-only — no per-visitor/per-account drill-down exists to be IDOR'd.                                                                                                                                                                                                                            |
| Query injection                    | Low                 | Every query in `product-analytics.ts` uses Drizzle's parameterised query builder — no raw string concatenation into SQL.                                                                                                                                                                                                                                                                             |
| CSP regression                     | Low                 | CSP's `script-src`/`connect-src` Google allowlist was already present pre-Phase-13 (an existing, disclosed SRS §6.2 deviation) and is unchanged by this phase — no new wildcard or broadened directive was introduced.                                                                                                                                                                               |
| XSS through consent UI             | Low                 | `AnalyticsConsent.tsx` renders only static, hardcoded copy and numeric/enum state — no user-supplied string is ever interpolated into the DOM.                                                                                                                                                                                                                                                       |

## Residual, disclosed limitations

- Consent revocation cannot delete data already transmitted to Google in a prior session, and
  cannot reach cookies outside CrawlPact's own domain — stated plainly in the privacy policy and
  `CONSENT_AND_ANALYTICS_PREFERENCE_MODEL.md`, not implied to be complete erasure.
- The global opt-in model does not itself constitute a legal-compliance guarantee for any specific
  jurisdiction — stated explicitly, not left implicit.
