# Requirements Traceability Matrix

**Level 2 document (Requirements and product intent)** — maps SRS requirement groups to
implementation, test, and production evidence. This document is corrected against the Phase 0
baseline (`docs/baseline/2026-08-03/`) as part of Phase 1's source-of-truth correction — see
`docs/status/CURRENT_STATE.md` for the current, capability-level product status and
`docs/baseline/2026-08-03/CAPABILITY_MATRIX.md` for its underlying evidence.

**Status vocabulary** (Phase 1, replaces the old Implemented/Tested/Verified scale): `satisfied` ·
`partially-satisfied` · `not-satisfied` · `superseded` · `intentionally-deviated` ·
`not-applicable` · `verification-blocked`. **Requirements status is distinct from capability
status** (the Phase 0 vocabulary of `verified-live`/`code-present-not-production-verified`/etc.,
used in `CURRENT_STATE.md` and the Phase 0 capability matrix) — a requirement can be
`satisfied` by code+tests while its underlying capability is only
`code-present-not-production-verified`, and the two should not be conflated. Owners are recorded
as roles, not personal names, per `docs/governance/DOCUMENTATION_GOVERNANCE.md`.

## How to update this document

When a requirement's implementation state changes, update its row in the same change — not as a
follow-up. Requirements documents must never be presented as proof that a feature is live —
production evidence for that belongs in `docs/status/CURRENT_STATE.md` and the Phase baseline
documents, cited here only by reference.
