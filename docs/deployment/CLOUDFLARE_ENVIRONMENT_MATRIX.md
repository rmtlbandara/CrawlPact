  `preview.crawlpact.com` Custom Domain is attached and healthy (`GET /accounts/.../workers/domains`
  lists it, zone `crawlpact.com`, service `crawlpact-web-preview`, enabled). Whether Google Auth
  Platform has since registered it as an Authorized origin could not be checked this session (no
  Google Cloud/OAuth tooling connected — see the Phase 1–3 closure `STARTING_STATE.md`); treat the
  `GOOGLE_CLIENT_ID` row above as unverified rather than resolved.
- **Preview's app-origin candidate was corrected 2026-09-10** (Phase 1–3 closure review):
  `app-preview.crawlpact.com` is a sibling of `preview.crawlpact.com`, not a subdomain of it, so
  pairing it with `WEBAUTHN_RP_ID=preview.crawlpact.com` would have silently failed every WebAuthn
  ceremony the moment it was ever attached (RP ID must be the origin's effective domain or a valid
  label-suffix of it). Corrected to `app.preview.crawlpact.com`, a genuine subdomain the existing
  RP ID validly covers. Still not attached to anything — this only fixes the candidate value before
  anyone acts on it, it does not enable nested Preview app-origin support.
- **Both environments have `workers_dev` enabled** (confirmed live 2026-09-10:
  `GET .../workers/scripts/crawlpact-web/subdomain` → `{"enabled":true,"previews_enabled":true}`).
  Production has a working Custom Domain, so its `workers.dev` exposure is redundant, and the
  Phase 1–3 closure directive flagged disabling it — **not yet done**: this is a real,
  account-level Cloudflare change being held for explicit owner sign-off rather than made
  unilaterally from a reconciliation pass (see the accompanying closure report). Preview currently
  depends on it and is not in scope for that change.
- The `SESSION` KV binding exists solely to satisfy `@astrojs/cloudflare`'s own built-in session
  feature default — it is not read by any CrawlPact application code (real sessions are D1-backed,
  ADR-0004). See `CLOUDFLARE_CONFIGURATION.md` for the full explanation.
